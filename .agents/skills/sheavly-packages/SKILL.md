# Sheavly workspaces

Every workspace in `packages/` (libraries) and `apps/` (front ends), from its `package.json`:
what it is for, its domain, and what it depends on at runtime. Start from its README: what it is
for, its public API and an example. Its `docs/` folder goes deeper.

To decide which one new code belongs in, use the rules in "Where code goes"
(`.agents/skills/sheavly/layers.md`): generic or coding first, then a choice a UI makes goes in an app,
and a new package only when nothing that exists owns it.
