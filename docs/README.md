# Sheavly harness docs

How the parts fit, across the workspaces. Each workspace documents itself: its `README.md` is the
first place to look (what it is for, its public API, a short example), and its `docs/` folder
goes deeper. Open work is in [GitHub Issues](https://github.com/Sheavly/code/issues).

| Doc                                      | What it covers                                                                     |
| ---------------------------------------- | ---------------------------------------------------------------------------------- |
| [vision.md](vision.md)                   | Why the harness exists, the principles it follows, and the roadmap                 |
| [overview.md](overview.md)               | The layers and their graph, the UI's role, packages, trust, errors                 |
| [shipping.md](shipping.md)               | How Sheavly is installed and run: packages, the command, the always-on server      |
| [Agent prompts](agent-prompts/README.md) | Minimal shared instructions, research evidence and evaluation limitations          |
| [Summary](summary/README.md)             | How a long history is shortened: the research, and [the design](summary/design.md) |

Workspaces:

| Workspace                                                       | What it is                                                                                                                                                                                            |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`@sheavly/backend`](../apps/backend/README.md)                 | The harness backend: builds each run from its settings (provider, model, tools, hooks, trust) and serves its conversations to every UI over HTTP.                                                     |
| [`sheavly`](../apps/sheavly/README.md)                          | The sheavly command line: the one command of the whole product, which runs the server and the terminal.                                                                                               |
| [`@sheavly/terminal`](../apps/terminal/README.md)               | The terminal front end: the demo (one prompt, printed as it happens) and the workbook (stored prompts, saved runs, step, diff and real-model checks).                                                 |
| [`@sheavly/agents`](../extensions/agents/README.md)             | Sub-agents, the background task tools, command output reading and history search, as one extension that other extensions share their tools with.                                                      |
| [`@sheavly/coding`](../extensions/coding/README.md)             | The coding extension: the file tools, run_command and start_service, and the hooks that go with them.                                                                                                 |
| [`@sheavly/web`](../extensions/web/README.md)                   | Public web reading and search tools (web_fetch, web_search), shared with sub-agents.                                                                                                                  |
| [`@sheavly/client`](../packages/client/README.md)               | The harness's HTTP client for UIs: every route of the API (API_ROUTES), typed and parsed with the contract's schemas, and its SSE streams. Only apps depend on it.                                    |
| [`@sheavly/core`](../packages/core/README.md)                   | The code contracts tools, hooks and providers are written against: defineTool, defineHook, defineAdapter, Provider and the Environment an app passes in.                                              |
| [`@sheavly/eslint-config`](../packages/eslint-config/README.md) | The shared ESLint config and the harness/* rules every workspace is checked with: file kinds, the import graph, public APIs, one definition per type.                                                 |
| [`@sheavly/extension`](../packages/extension/README.md)         | The extension lifecycle: the Extension contract extensions are written against, and the host that activates them in dependency order, isolates failures, gates trust and merges what they contribute. |
| [`@sheavly/host`](../packages/host/README.md)                   | The services one run shares: the session, task and approval registries around the provider a UI picked, and the run-service keys extensions read (runServices). No tools, hooks, settings or UI.      |
| [`@sheavly/loop`](../packages/loop/README.md)                   | The agent loop: streamAgent and runAgent, its events, the ordered queue, aborts and hooks. Nothing about files or which tools a run has.                                                              |
| [`@sheavly/process`](../packages/process/README.md)             | The process runner: spawns a command or script without a shell, scrubs secret env, enforces deadlines, and stops what it started when the host exits. Nothing about files or code.                    |
| [`@sheavly/protocol`](../packages/protocol/README.md)           | The wire contract: every event, update and answer the harness sends a UI or accepts from one, as zod schemas.                                                                                         |
| [`@sheavly/providers`](../packages/providers/README.md)         | Model backends: the Responses and Messages protocols, their backends (OpenAI, Azure, Amazon Bedrock), the adapter registry and the provider switch. A UI builds its provider here.                    |
| [`@sheavly/runtime`](../packages/runtime/README.md)             | The stateful services a run uses: sessions, background tasks and approvals. Nothing about files or code.                                                                                              |
| [`@sheavly/storage`](../packages/storage/README.md)             | The user's data on disk: the folder layout under ~/.sheavly, file-backed stores for conversations, models, credentials and profiles, and the one atomic JSON write they share.                        |
| [`@sheavly/summary`](../packages/summary/README.md)             | Built-in summarizers: rules-only sections and a model-based writer, written against the core Summarizer contract                                                                                      |
| [`@sheavly/testing`](../packages/testing/README.md)             | Test fakes every workspace's tests share: scripted and routed providers, fake fetch, a tool runner. Tests and fakes only.                                                                             |
| [`@sheavly/tools`](../packages/tools/README.md)                 | The generic tools a UI can include: sub-agents (start_agent, message_agent, report_status) and the background task tools. No files, no commands.                                                      |
| [`@sheavly/workspace`](../packages/workspace/README.md)         | A project on disk, for coding UIs: path confinement to the workspace root, working roots, file reads and the shared scratch folder.                                                                   |

The same list, with each workspace's role and dependencies, is the `sheavly-packages` skill (`.agents/skills/sheavly-packages/`), which routes the agent; both are generated by `npm run graph`.

When a workspace changes, its README and docs change with it. Cursor's stop hook reminds the
agent once: if a workspace's source changed but none of its docs did, it asks to update them.
