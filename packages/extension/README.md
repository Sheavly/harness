# @sheavly/extension

The extension lifecycle: the Extension contract extensions are written against, and the host that activates them in dependency order, isolates failures, gates trust and merges what they contribute.

An extension is one unit of what a run includes. The framework puts no category or policy on it:
what an extension can and cannot do is its own to define, so others can build extensions without
changing this source. It ships a data-only `sheavly.json` manifest that declares its unique
kebab-case `name`, `dependsOn`, services, settings and the names it contributes, and an `activate`
that returns its contributions: tools, hooks, work kinds, system-prompt `instructions` sections and a replacement `baseInstructions` (each behind a host-offered grant, `system-prompt:extend` and `system-prompt:replace`, and the text's content is review-only), and the event kinds and notice topics it
may emit through `context.emit` (held to the manifest's `emits`; the app supplies the sink, and the host disarms `emit` when the extension stops; no scoped service hands out `publish`, `queueNotice` or `publishTask`, though Node code could reach a registry by importing the runtime). The host holds it to its manifest
(a name ending in `*` declares names that are not known in advance, such as a workspace's own hooks).
The manifest is not a sandbox: an extension is Node code, and the host checks only what it mediates
(see [What the manifest is not](docs/manifest.md#what-the-manifest-is-not)).
Extensions share typed services with each other through `defineService` (`services.provide` for
one shared value, `services.provideFor` for a value built per consuming extension, so a service an
extension provides can declare `services.grants` in its manifest and enforce them with
`requireGrant`; the consumer a factory receives is a frozen snapshot, grant names are global
strings so a provider names them after its capability, and a `disarm` that throws is contained and
reported (one that returns a rejected promise is collected best-effort when it settles; one that
hangs synchronously blocks `deactivate()`; what a failed activation closed the host with is
returned once by the next `deactivate()`); see [Services](docs/services.md#services-an-extension-provides-per-consumer)), and the app supplies
run-level services any extension can read (`hostService`, or `hostServiceFor` for one built per extension and limited to the `grants` its manifest asks for; the host verifies those at activation and a service checks them with `requireGrant`). An app builds an `ExtensionHost`, which
activates them in dependency order, reports an extension that fails without stopping the rest,
skips code that is not trusted and merges what they contribute for the app to hand to the loop.
Depends on `@sheavly/core` and `@sheavly/protocol` (the envelope types and size caps) and, for types only, on `@sheavly/runtime` (the scope views the run-service keys carry).

```ts
import { defineExtension, settingKey } from '@sheavly/extension/extension/extension.utils';
import { readManifest } from '@sheavly/extension/manifest/manifest.helper';
import { ExtensionHost } from '@sheavly/extension/host/extension-host.service';

// extensions/notes/sheavly.json declares the name, the setting `notes.max-notes` and the tool
// `add_note`; src/<folder>/ and dist/<folder>/ are both two levels below the package root.
const manifest = readManifest(new URL('../../sheavly.json', import.meta.url));
const MAX_NOTES = settingKey({ manifest, name: 'notes.max-notes', type: 'number' });

const notes = defineExtension({
  manifest,
  activate: ({ settings }) => ({ tools: [createNoteTool(settings.get(MAX_NOTES))] }),
});

const host = new ExtensionHost({ extensions: [notes], settings: { 'notes.max-notes': 100 } });
const { contributions, settings, failed, skipped } = await host.activate({ signal });
// contributions: { tools, hooks, instructions, baseInstructions, workKinds, events, notices }, merged in activation order, hooks placed
await host.deactivate();
```

Tests build extensions with `fakeExtension`, `fakeHook`, `fakeInstruction` and `fakeTool` from
`@sheavly/extension/testing/extension.fake` (`serviceGrants` declares the grants of a service the
fake provides). `fakeGrantedProvider` and `fakeGrantedConsumer`
(`@sheavly/extension/testing/granted-service.fake`) are a provider whose service enforces a grant
with `requireGrant` and a consumer of it. `assertServiceEnforcesGrants`
(`@sheavly/extension/testing/service-grants.fake`) is what a provider's tests call: for each grant
its manifest declares for a service, the call listed for it must refuse a consumer without it
(see [Services](docs/services.md#services-an-extension-provides-per-consumer)).
`outside-consumer.test.ts` builds, type-checks and runs an extension from public exports only (see
[Services](docs/services.md#an-extension-built-from-public-exports-only)).
