# Who changes with the wire model

Every workspace that reads or writes the stream, a session update, a task or an approval today,
found by what imports the protocol's `stream/`, `session/`, `task/`, `approval/` and `queue/`
modules (not by memory), and what changes in each. The model is
[wire-model.md](wire-model.md), and each entry's place in it is in
[the mapping](wire-model-mapping.md). The issues are the ones #438 split the work into, and each
updates its own docs.

The issue that started this design listed loop, runtime, host, storage, backend routes, client,
terminal, replay and the workbook. The search found more that depend on the shapes: `core`,
`tools`, `workspace`, `extension`, `extensions/coding`, `testing`, and `eslint-config`. They are
in the table, and they are mostly keyed by a session id that becomes a node id.

## Outside this repository

A front end in another repository (the tmux client) that follows a conversation through the
stream moves to subscriptions with the client's change (#430), and one that reads stored history
from the disk does not survive the per-channel layout (#425), which is what #416 and #451 are
about. The protocol is not frozen until this is built, so none of them has a compatibility to keep:
see "Version" in [the contract](contract.md#version).
